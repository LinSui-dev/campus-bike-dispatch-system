# 开发入口

目标是六人各自使用智能体独立并行开发一个可运行、可复现、可验收的课程系统。当前交付为文档、契约和开发骨架，不是已完成系统。

阅读顺序：README与AGENTS → 01需求、02总体、10分工 → contracts/README与Python端口、Schema → 自己的roles任务书 → 相关设计与09测试、11集成。

已确认：四人主要开发，一人联调测试，一人文档；地图和数据纳入开发分工；仅P0，不做P1/P2，不安排时间计划。启动后空闲，点击开始才执行；交互和批量合计同一时间一个实验。重置询问保存或舍弃，异常退出不创建不完整历史。请求在时间段内随机分布，复现要求相同配置、种子、版本和命令序列。预测使用库存约束的确定性期望推演，不读取未来实际请求。

正式素材由D组织提交，当前fixture仅用于并行开发。待补信息：成员姓名、组号、正式地图及道路长度依据、需求率来源；不阻塞虚拟夹具开发，不得替团队编造。

正式分发前先按11建立Git基线与独立工作目录。个人执行步骤在roles，交接流程与填写格式在handoffs/README与TEMPLATE。01定义范围，02～08定义行为，contracts定义机器字段与签名，09定义指标，10定义所有权，11定义协作，13定义逐项验收；任务书引用这些权威，不另设冲突口径。

当前分发契约为1.1.0，替代尚未开发的1.0.0草案，不要求业务兼容旧草案。工作目录、替身和固定端口支持并行开展模块工作；真实集成、正式素材和课程结论仍存在必要依赖，不承诺无需协调。
