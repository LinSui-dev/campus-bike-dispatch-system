给B的最小回调方式（在其`run_batch(request, run_once, on_progress)`内）：

```python
spec = {
    "batch_id": request["request_id"], "scenario_id": scenario_id,
    "algorithm": algorithm, "seed": seed, "params": request["params"],
    "dispatch_times_sec": request["dispatch_times_sec"], "batch_request": request,
}
```

由A工作者调用`ExperimentRunner().run_batch(request, manager.run_once, on_progress)`。run_once每组重建网络、引擎和随机源，执行并原子保存，不向B传DB或引擎；只允许持有batch槽的工作者调用，禁止用回调绕过全局槽。

给C的接口和恢复示例：启动后`/docs`与`/openapi.json`包含契约DTO。先GET `/api/v1/runtime`，interactive时按run_id连接`/ws/runs/{id}`并缓冲，再GET state，按seq合并。State.context含原始params与独立current_speed。错误如`{"code":"BUSY","message":"已有实验占用运行槽；暂停或保存失败时仍占槽","details":{}}`（409），当前缺失依赖为NOT_IMPLEMENTED（501）。测试中的合法运行例见owner_a/test_api.py；真实运行201仍需接真实B/D后复验。

## 7 给F的文档素材

- 实现采用离散边界“运输到达→骑行到达→旧等待→借车→预设触发→采样”，公开sim_time是刚处理的边界而非cursor。请求保留实际整数秒和执行桶起点，离散误差小于一步；骑行/运输最少一步到达。
- `random.Random(seed)`与稳定OD/边界/ID排序保证同版本复现；算法只得到完整当前State，不得到未来请求列表。墙钟倍速只由运行管理器用于调度step，指标只用模拟时间。算法耗时为观察量，不参与业务确定性比较。
- 车辆守恒为stock＋rides＋waiting＋transporting；预留等于未到货任务量，普通还车遵守capacity-stock-reserved。非法调度整批校验后才扣减，过期库存/容量不够即拒绝。运行不使用真实租车或卡车资产模型。
- 历史保存完整网络/站点/OD/参数/版本/命令快照；不以当前站点外键破坏旧历史。异常不保存未完成run，save失败回滚且交互槽仍保留供重试或明确舍弃。
- 真实素材：本次仅源码、XML和文本日志，无界面截图、实验效果图或论文结论；fixture来自仓库自建虚拟图/OD，来源说明见data/fixtures/sources.md，不是校园调查。没有新增外部地图、AI地图或许可不明素材。
- 实际贡献仅A归属的后端实现、67项模块测试、依赖补齐、提案与交接材料；不编团队其他人的贡献或评分。
