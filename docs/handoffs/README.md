# 个人交接报告

handoff是“模块交接报告”，让接收者不依赖口头解释，就能找到提交、安装运行、调用接口、复现验收并了解限制。它不是日报，不转移代码所有权，提交报告本身不代表验收通过。

## 谁写谁读

A～F各自维护同名子目录，复制[TEMPLATE](TEMPLATE.md)填写。A/B/C/D交给E联调，E向团队和F交验收记录，F交课程材料供E核对。其他成员阅读调用方式，F提取真实技术素材与已核实证据。

一般只有对应成员修改自己的报告，唯一例外是E在模板第8节写接收结论。E在集成分支填写；成员后续更新前同步，F不改原始结果。handoff说明单个模块怎么接，docs/integration/results记录跨模块复验和系统结论。

## 生命周期

1. draft：开发时可记录入口、依赖和问题，不能宣称可验收。
2. ready：本次明确范围的AC全部自测通过，提交代码和报告，将SHA与范围交E。
3. E检查所有权、契约、干净安装和实际测试，写accepted或returned及证据。
4. returned由原所有者修代码、更新同一报告并再次交E；新提交不能自动继承旧accepted。
5. accepted只表示该范围被接收，不等于该成员全部任务或整个P0完成；全系统以13门禁为准。

报告最低内容已经展开在模板：基线提交、范围、公开入口、安装复现、AC/T逐项预期与实际证据、Mock、真实接入、依赖、契约、限制、给F的素材和E结论。无内容写理由，未执行如实写未执行。
