# 仿真引擎设计

## 参数

默认120分钟、step=60秒、骑行12km/h、运输10km/h、倍速60、seed42。duration_sec须整除step。step为1～300整数、时长1～1440分钟、倍速0.1～600、物理速度0.1～100。整数秒，米，辆·米。界面时刻=场景start_minute+sim_time/60，跨午夜显示次日。

## 生成器v1

用标准库random.Random(seed)，不用全局随机源。OD按(origin_id,destination_id)排序，按步边界及倍率边界分割时间半开区间，未配倍率默认为1。每常率区间用指数到达间隔Poisson过程：t += -log1p(-rng.random())/(rate_per_min*multiplier/60)，到区间末停止，零率不抽样。保存time_sec=floor(t)，稳定递增事件id，最终按(time_sec,id)排序。固定生成器版本与Python版本。先生成供策略复用，不传给算法。

事件、骑行、任务ID分别使用req-/ride-/task-前缀与12位补零序号，保证字符串排序与生成次序一致；计数在每次新运行从1开始，跨运行由run_id区分。

请求在时间段随机分布，整数秒可同秒；事件归入所在步[floor(t/step)*step,下一边界)，在该步起点借车。保留time_sec与executed_sec，量化误差小于一步，报告离散近似。到达=executed_sec+max(step,ceil(distance/speed_mps/step)*step)，零距离也至少下一步。

## step与顺序

初始now=0；step处理当前now后推进一边界，首次处理t=0。顺序：到期运输按task_id、到期骑行按ride_id、此前等待按ride_id、本步借车请求、预设调度触发、采样。新等待本步不重试。库存时间积分用前一处理后状态覆盖到当前边界，t=0无积分。

内部cursor指下一个待处理边界，返回State.sim_time_sec是刚处理的边界，不提前显示cursor。A在POST runs返回前执行首次step，公开快照统一是t=0处理后状态；初始处理前快照仅内部测试使用。完成最后边界后step幂等返回终态。

duration边界只处理到达和此前等待并采样，不生成请求或调度，不再推进。初始快照与t=0业务后快照seq不同，持久化同sim_time只留业务后指标。暂停不step，倍速只墙钟。

## 借还与运输

空站立即借车失败，不等待不改站；否则扣1。首次到达仅记一次首次还车尝试。可用容量=capacity-stock-reserved_inbound。有位归还，无位按(distance,id)选最近可达有位站，增加实际改道路段距离并重新计到达；无候选进入等待，每步重试。骑行改道不预留位置，可能再次改道。等待不计骑行利用率。

引擎执行调度前聚合校验所有源库存与目的预留，整批原子接受或拒绝。扣源、加目的预留，任务并行，运输到期释放预留并入库且幂等，不模拟卡车。未到货结束不凭空归还。

手动命令在最近已发布边界执行，日志记sim_time、command_seq、请求参数和结果；下步不重复触发。批量触发必须step对齐，0≤t<duration，排序去重。复现按模拟边界和命令序号重放，墙钟延迟不进入结果。

## 不变量与结束

每阶段校验总车数=库存+骑行+等待+运输；stock≥0、stock+reserved≤capacity；预留等于未到货任务量；每请求计一次。stop保存stopped并释放；reset显式save=true保存、false舍弃，已保存不重复。异常丢弃本次，不恢复。保存失败保留内存待用户重试或舍弃，不允许新实验覆盖。
