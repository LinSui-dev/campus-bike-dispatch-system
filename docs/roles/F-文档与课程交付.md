## 从开工到交接的步骤

下列是本模块内部执行路径，不要求其他成员按顺序等待。可以穿插测试，但每步交付必须可核验。

|步骤|工作|具体动作|该步产物|
|---|---|---|---|
|1|核对原始要求|读取根课程要求与论文模板，提取页数/内容/字体/PPT/命名清单；保留原件。|课程检查表，不自行补造要求。|
|2|组织资料与结构|建立论文/PPT结构、章节和素材索引；收集A～E技术素材与来源，代码未就绪也可整理结构。|每项材料的提供者、证据路径、缺失状态。|
|3|维护开发文档|根据已接受提案和真实实现更新README/设计，维护链接与分工；不单方面改变接口或业务规则。|文档与Schema/代码一致，未实现明确标注。|
|4|撰写论文|按课程结构完成≥30页，使用真实图表与引用，说明合成需求、模型简化、算法局限和失败项。|source中的可编辑论文，未执行实验不填结论。|
|5|制作答辩PPT|覆盖问题架构功能实验，逐页标页码讲述人；贡献与评分依据实际工作，不预填团队分数。|可编辑PPT与成员核实的贡献表。|
|6|版式与事实核验|渲染检查论文分页字体图表、PPT逐页查看；与E核对版本/指标/截图，修正问题后复验。|渲染和事实核验记录，不能以文本检查代替版式检查。|
|7|交付与handoff|在source/final/INDEX组织文件，确认组号姓名后按课程命名；交E核对，不发布未经核实内容。|最终论文PPT、运行说明、来源索引和ready报告。|

## 验收与命令

AC-F01、AC-F02主责，配合E核对所有证据；课程交付不属于新功能扩展。

以下命令在本人的项目根目录执行，依赖安装见README/11；服务运行以Ctrl+C停止，数据库必须本目录独立或测试临时目录。

```powershell
python scripts/check_baseline.py
```

链接检查只是结构检查；≥30页、原模板格式、PPT每页标识、真实来源贡献、渲染与E事实核对全部通过才交最终材料。工具具体命令记录在自己的报告中。

每个AC填写输入、操作、预期、实际与证据，失败和未执行如实记录；不以Mock或类型构建通过代替真实系统验收。按范围分批交接允许，但不能省略剩余P0。
