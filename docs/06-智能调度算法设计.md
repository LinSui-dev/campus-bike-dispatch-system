# 智能调度算法设计

## 端口

B提供DispatchService.estimate、plan和ExperimentRunner.run_batch，见contracts/python_interfaces.py。纯计算，不读DB/HTTP/未来请求。A注入NetworkPort及同步run_once；B组织组合，不自行绕过全局槽。

## 库存约束期望预测

默认窗口30分钟，截断到场景终点，预测子步与引擎step一致。复制当前浮点期望库存、预留、已知骑行、等待和运输。每步按引擎的到达、等待、借车顺序推演。已知在途仅入队一次，未来借车由OD率与倍率积分；同站多个OD争库存按期望需求比例分配，不超当前库存。未来骑行按道路时间入队，窗口后到达不计R。

满站预测按(distance,id)找可达空位站，分数车辆可拆分，剩余等待，改道至少一步。运输到货影响库存与预留，但不计骑行还车。B是OD率积分得到的潜在借车请求量（expected_borrow），无论届时是否有车；另记受库存限制的预计实际借出expected_served_borrow，只有后者才能产生未来骑行与还车。R是窗口内实际归还到该站的骑行/等待（含已知与预测新骑行），不重复计算已知在途。这样空站不会因为借不出车而被预测成低需求。未来尚未生成的调度不预测，不额外随机抽样。此为流体期望近似，不是随机过程精确期望，论文说明局限。

snapshot为当前边界处理后状态，不能重算当前桶。预测未来借车桶从now+step开始，计入执行时刻小于window_end的桶，并在window_end处理到达；每桶期望量按其完整区间与窗口的交集积分，末桶截断。首次当前边界的调度预测发生在本步借车之后、采样之前，遵循相同规则。预计到达使用同一向上取整规则。

## 供需

S默认5；T=clip(floor(max(0,B-R+S)+0.5),0,capacity)。E=stock+reserved_inbound；supply=min(stock,max(0,E-T))；demand=min(capacity-stock-reserved_inbound,max(0,T-E))。B/R/expected_served_borrow浮点，其他整数，0≤expected_served_borrow≤B。none同样估算目标但不发任务。目标为简化启发式，不保证窗口每时刻无缺车。

## 优化

贪心按(distance,source_id,destination_id)排序，每对分配min(供给,需求,预算)，不可达跳过；不连通图可能不最大流。预算默认50。

最小费用流：超级源→源点容量预算，源点→供给，供给→需求，需求→汇。先maximum_flow_value求F，再超级源demand=-F、汇点demand=F、其余0，以network_simplex最小费用。F=0空返回。优化距离floor(distance_m+0.5)整数米，报告成本用原始米数；最优性针对整数费用模型。稳定节点边插入、固定NetworkX版本、计划按(source,destination)排序以复现并列最优。

执行统一输出source_id,destination_id,quantity,distance_m,route；A重新校验原子发车。B不得直接扣库存。

## 批量

输入场景×算法×种子，保留输入顺序并拒绝重复。每组重建引擎、网络、随机源，注入run_once执行保存。单项失败记录error/run_id=null继续。状态running/completed/partial_failed/failed。汇总每场景每策略均值、样本标准差（n<2 null）、有效n，null不当0。

默认4场景×3策略×种子42～46=60组。120分钟触发[0,900,1800,2700,3600,4500,5400,6300]，必须step对齐；none忽略但保留配置。不同策略同种子复用生成规则与初始数据。全批次占槽，不能交互插入实验。
