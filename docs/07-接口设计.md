# 接口设计

## 基本约定

前缀/api/v1，JSON。GET/PATCH/PUT和动作200，创建201，DELETE204，批量启动202。列表统一{items,total}，本原型不分页。ID字符串，调用方生成站点/场景/配置UUID，重复409 DUPLICATE_ID。完整DTO字段权威为contracts/schema.json，跨字段规则见设计文档。未知请求字段拒绝。

错误统一{code,message,details}，details对象。400业务参数，404不存在，409冲突，422字段校验，500内部错误；未实现501 NOT_IMPLEMENTED。A把FastAPI默认错误转换为统一格式，不暴露堆栈。日期ISO8601带时区，显示Asia/Shanghai。

## 静态与配置接口

|方法 路径|请求|响应|
|---|---|---|
|GET /health|无|{status:"ok",stage:"scaffold"或"implemented"}|
|GET /runtime|无|{mode:idle/interactive/batch,run_id:null或字符串,batch_id:null或字符串}|
|GET /map|无|{profile,image_url,width,height,network_version,synthetic,snap_tolerance_px}|
|GET /roads|无|RoadNetwork|
|GET /stations|无|List<Station>|
|POST /stations|StationCreate（不含道路派生字段）|标准化Station|
|PATCH /stations/{id}|StationPatch|标准化Station|
|DELETE /stations/{id}?clear_related_od=false|无|204或RELATED_OD|
|GET /scenarios|无|List<Scenario>|
|POST /scenarios|Scenario，is_preset=false|Scenario|
|GET /scenarios/{id}|无|Scenario|
|PATCH /scenarios/{id}|name/start_minute/duration_min/description子集|Scenario|
|DELETE /scenarios/{id}|无|204或PRESET_SCENARIO/IN_USE|
|PUT /scenarios/{id}/od|{od_demands:[OD]}整体替换|Scenario|
|GET /configs|无|List<Config>|
|POST /configs|Config|Config|
|PATCH /configs/{id}|name/scenario_id/params/seed/algorithm子集，params整体替换|Config|
|DELETE /configs/{id}|无|204|

List<X>指{items:[X],total:number}，不是裸数组。空列表total=0。站点PATCH坐标改动时不要求前端计算road_offset，由D投影后返回标准值；容量与库存仍需合并校验。配置CRUD仅idle，非idle返回409 BUSY。OD倍率时间为相对场景起点分钟，不是钟表分钟；基础倍率1，覆盖区间使用配置倍率而非叠乘。

StationCreate必填id/name/campus/zone/x/y/capacity/initial_stock/active，禁止传road_edge_id/road_offset。StationPatch至少一个可编辑字段，禁止id和道路派生字段；x/y必须同时提交。A负责Schema、ID唯一、库存容量和编辑冻结校验；PATCH先查旧值、合并后移除派生字段，形成完整StationCreate交D.validate_station。D负责投影、边界与可达性，返回完整Station；A事务保存并重建路网服务。返回坐标采用投影后值，C必须用响应更新标记。D校验已有id时排除其旧接入点，不误判为新建重复；A才负责新建ID冲突。

## 运行接口

|方法 路径|请求|响应|
|---|---|---|
|POST /runs|RunRequest|State（201）|
|GET /runs/{id}/state|无|State，仅当前/仍留内存结果|
|POST /runs/{id}/control|Control|State，reset例外见下|
|GET /runs/{id}/supply-demand|无|SupplyDemand|
|POST /runs/{id}/dispatch|{request_id:字符串}|{request_id,tasks:[Task],supply_demand:SupplyDemand}|
|GET /runs/{id}/tasks|无|List<Task>|
|GET /runs|无|List<RunSummary>，仅已保存历史|
|GET /runs/{id}|无|{run:RunSummary,snapshot:ConfigSnapshot,commands:[Command]}|
|GET /runs/{id}/metrics|无|List<{sim_time_sec,metrics:Metrics,stations:[StationState]}>|
|POST /batches|BatchRequest|BatchResult（202）|
|GET /batches/{id}|无|BatchResult|

RunRequest直接包含scenario_id与完整params，不传config_id，配置页面先展开保存的Config。params.duration_min覆盖Scenario.duration_min；OD时段必须在运行时长内，否则400 INVALID_PERIOD，不悄悄截断；预设场景正常使用相同120分钟。种子为uint32。算法none/greedy/min_cost_flow。批量的request_id也是batch_id；B收到完整BatchRequest，以该ID填RunSpec.batch_id。交互run_id由A生成。

Control互斥结构：{action:"pause"}、resume、stop；{action:"speed",value:number}；{action:"reset",save:boolean}。reset响应{mode:"idle",saved:boolean,run_id:string}，不是State。UI取消不发请求。stop保存，重复不重复写库；pause/resume同状态幂等，已结束不能resume。reset后A保留轻量幂等回执直至进程退出，相同run_id同选择重试返回相同结果，不重复保存；选择不同返回409 IDEMPOTENCY_CONFLICT。

dispatch仅running/paused交互运行可调用，用本次配置算法，none空计划；目标偏差与供需仍可计算。不允许中途切策略和物理参数，只能改speed。completed/stopped禁止dispatch。供需查询可以只读历史末态但不得重新发车。

POST runs/batches/dispatch含request_id；进程内幂等，同ID相同payload返回原结果，同ID不同payload409 IDEMPOTENCY_CONFLICT。请求超时客户端以相同ID重试。新ID意味着新命令，但运行槽和预留必须重新校验。业务失败回执也缓存，修正payload用新ID。

## 状态与快照

State含完整StationState、rides、waiting、tasks、Metrics、seq和context（Schema字段全部必填），预测所需已知在途必须存在，不能只传前端指标。status为running/paused/completed/stopped/aborted；aborted仅内存通知，不保存不完整run。UI非活跃状态从runtime判断，不能把历史GET当恢复运行。

context为RunContext：scenario_id、scenario_name、start_minute、seed、params、current_speed、network_version。params是本次冻结初始参数，current_speed是当前墙钟倍速，speed命令后只更新后者并增加seq。A在同一运行锁内组装快照与上下文，不能出现新seq配旧倍速。此字段只补足恢复显示，不开放修改物理参数。

刷新恢复步骤：C先GET runtime；idle只加载配置，不自动开跑；interactive取run_id，WS连接后缓冲，再GET state并以seq合并，恢复场景、当地时间、种子、参数、倍速和控制按钮；batch根据batch_id GET批次进度，禁用交互控制。若恢复期间运行结束或reset导致state返回404，重新GET runtime并转入idle或新的活动对象，不能自动创建运行。运行完成后可保留最后State供结果显示，但runtime回idle；用户看历史使用历史API。

Config保存id/name/scenario_id/params/seed/algorithm。ConfigSnapshot包含Versions、完整network/stations/scenario/params、seed/algorithm/dispatch_times_sec/commands与batch_request（交互为null）；无需依赖当前站点表。RunSpec带完整batch_request供子运行快照保存。业务端口构造固定为：

```python
NetworkService(network, stations, snap_tolerance_px=40)
DispatchService()
Engine(run_id, config_snapshot, network_service, dispatch_service)
ExperimentRunner().run_batch(batch_request, run_once, on_progress)
```

具体入口为app.network、app.dispatch、app.engine、app.experiments的导出。run_once(RunSpec)→RunOutcome，A负责执行与保存，异常抛出给B转换失败item；on_progress(BatchResult)为同步回调，A负责线程安全发布。不得把引擎对象或DB会话传给B。B在调用run_once前发running进度、每项后发进度，最后返回汇总。API可202时items全pending，不伪造已经完成。

## WebSocket

/ws/runs/{id}推{type:"state",...State}或{type:"error",...Error}；type为传输封套额外字段，不放入State Schema。seq按run变化递增，GET不增加；每墙钟秒合并推送，暂停/结束即时。reset先推最后stopped/completed快照后关连接，控制响应驱动UI回idle。未知run连接拒绝，给明确错误，不订阅其他运行。

重连先WS缓冲，再GET state，丢弃seq≤快照的消息，应用更大的；断线可每秒GET state降级。页面切换不能断后端运行。历史API不支持逐事件回放。

## 批量与异常

BatchResult含id/status/total/finished/items/aggregates。completed全部成功，partial_failed部分失败，failed全部失败，interrupted是进程中断后由已保存子运行构成的只读摘要；不能自动恢复。item.run_id仅成功有值，error仅失败有值；finished=completed+failed数量。统计按场景与策略，每指标{mean,stddev,n}；null排除，n<2标准差null。Schema为权威。
