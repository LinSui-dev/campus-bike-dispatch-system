# A：批量汇总保存失败的重试入口（待E协调）

状态：proposed，未修改contracts或他人文件。基线398d38435ca508450c0de866a0c3537169a26851，契约1.1.0。

## 现有约定和缺口

03规定成功子运行单独提交、结束写批次汇总；02/05规定结果保存失败保留内存并可重试或舍弃。07现有control只适用于交互run，batch只有POST启动和GET查询；缺少“所有子运行完成，但最后批次汇总事务保存失败”的重试/舍弃协议。不能单方面增加路由、改变POST同request_id返回原回执的语义，或把GET变为写操作。

## 当前A实现

子运行事务失败抛给ExperimentRunner，由B按原契约记录failed item并继续。批次最终汇总事务失败时GET batches返回统一500错误；内存保留进度和错误，已提交子运行保持不变，全批次工作者退出后释放槽。重启可按batch_id从已提交子运行恢复interrupted只读摘要，不能自动续跑。当前没有汇总写入重试入口，未声称此分支完成恢复验收。

## 建议E决定

建议保留GET只读和POST启动幂等性，协调B/C/A确定是否新增批次动作，例如POST /batches/{id}/control，区分retry_save与discard_summary；精确DTO、槽是否继续保留、内存回执和UI操作由E协调后定。另一选择是明确文档将该失败分支限定为只读interrupted，用户重新开展新批次。以上均是提案，不是已冻结的新业务约定。

影响A的运行管理/持久化、B的最终结果回调、C的错误与恢复展示、E契约和失败注入验收、F文档。迁移需E更新版本/Schema/示例/测试后A实现；目前不修改公共接口。

验证计划：在成功保存子运行后注入save_batch事务失败，检查无半条batches、子运行可查；按最终协议重试只保存汇总且不重复run_once，或明确舍弃；刷新与重启不伪造完成状态。
